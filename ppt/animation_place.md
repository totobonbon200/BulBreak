# 애니메이션 시트 배치

## 제약시스템 공통 규칙 — 최신 확정 사항
- 제약시스템이 동작하는 동안에도 게임오버 시스템은 동작한다. 이를 위해 **일반 게임오버 시스템과 별도로 제약시스템 전용 게임오버 시스템을 만든다.**
- 미로 ↔ 전투의 일반 전환 중에는 기존 게임오버 금지 규칙을 유지한다. 단, 전환 중 제약시스템이 동작하는 구간에는 제약시스템 전용 게임오버 판정을 적용한다.
- 전용 게임오버의 구체적인 발생 조건, 타이머·체력 사용 여부는 아직 미정이며 임의로 확정하지 않는다.
- 제약 안내는 아이작처럼 **왼쪽에 제약 관련 그림, 오른쪽에 짧은 설명글**을 배치한다.
- 설명글은 **최대 2줄**, **각 줄은 최대 4문장**으로 제한하고 짧게 작성한다. 자동 줄바꿈을 포함한 실제 표시도 2줄을 넘지 않게 한다.
- 기존 제약 안내 시간 약 1~2초와 방향키 전용 조작을 유지한다. 미로의 통로·벽·입구·출구, 전투 주인공의 실시간 행동과 적의 행동 큐도 유지한다.
- 이 규칙은 기존 문서의 제약시스템 관련 게임오버 금지·예외 설명보다 우선한다. 현재는 기획 반영이며 코드 구현 완료를 뜻하지 않는다.



## 좌표 기준
- 문서의 행·열 번호는 **왼쪽 위부터 1행 1열**로 센다.
- 코드에서 사용할 인덱스는 `(행 - 1, 열 - 1)`이며, 이미지 자르기 좌표는 `(x, y)` 순서임에 주의한다.
- 각 시트는 동일한 크기의 칸으로 나누어 사용한다. 실제 픽셀 자르기 좌표는 아래의 **해상도·비율 및 표시 크기** 규칙을 따른다.
- 재생 속도, 반복 여부, 상태별 프레임 선택 규칙은 별도로 정한다. 배치 정보만으로 이를 확정하지 않는다.

## 해상도·비율 및 표시 크기

### 기본 화면과 원본 크기
- 캔버스는 **800×600**으로 유지한다. 캔버스를 키우는 것만으로 이미지의 세부 표현이 복구되지는 않는다.
- 아래 크기는 현재 PNG 파일 기준이다. 파일 교체 시에는 실제 이미지 크기를 읽어서 계산한다.

| 시트 | 원본 크기(px) | 행×열 | 한 칸 크기(px, 분할 전 계산값) |
| --- | --- | --- | --- |
| 미로 | 800×400 | 2×4 | 200×200 |
| 캐릭터 | 600×600 | 4×4 | 150×150 |
| 캐릭터 공격 | 800×400 | 2×4 | 200×200 |
| 이펙트 | 800×400 | 2×4 | 200×200 |
| 결과 | 800×400 | 2×4 | 200×200 |

- 실행용 시트는 파일명에 크기가 붙은 새 PNG 5개를 사용한다. 기존 고해상도 원본은 보존한다. 전투·이펙트·결과 시트도 자원으로 로드하되, 미구현 게임 흐름은 추가하지 않는다.
- 축소 시 계단 현상을 줄이기 위해 텍스처 로드 전에 선형 보간을 설정한다. 배경과 게임오버의 200px 프레임을 600px로 확대하면 원본의 세부 표현 한계는 남는다.

### 시트 자르기
- 문서 기준 행·열을 0부터 세는 `r`, `c`로 변환한다. 이미지 너비·높이는 `W`, `H`, 전체 행·열 수는 `R`, `C`이다.
- 칸 경계는 `left = c * W // C`, `right = (c + 1) * W // C`, `top = r * H // R`, `bottom = (r + 1) * H // R`로 계산한다.
- pico2d의 아래쪽 기준 자르기 좌표는 `x = left`, `y = H - bottom`, `width = right - left`, `height = bottom - top`이다.
- `W // C`를 모든 칸의 너비로 고정해서 누적하지 않는다. 새 시트는 정확히 나누어떨어지며, 이 계산식은 이후 크기가 바뀌어도 나머지 픽셀을 포함한다.
- 이 계산은 칸 사이 간격과 바깥 여백이 없는 균등 분할 시트 기준이다. 그림이 잘리거나 옆 프레임이 보이면 실제 경계를 확인해 별도 좌표를 지정한다.

### 비율 유지와 권장 배치
- 잘라낸 프레임 크기를 `sw×sh`, 표시할 영역을 `bw×bh`라고 할 때, 배율은 `s = min(bw / sw, bh / sh)`로 정한다. 실제 그리기 크기는 **`sw * s`, `sh * s`**이며 영역 중앙에 배치한다.
- 캐릭터·타일은 가로·세로 비율을 유지한다. 배경·게임오버 이미지는 예외로 캔버스 전체를 채운다. 표시 영역은 아래 표의 크기이며, 실제 이미지 크기는 비율 유지 계산 결과를 사용한다.

| 대상 | 표시 영역 및 위치 | 적용 규칙 |
| --- | --- | --- |
| 전체 화면 배경 | 800×600, 중심 `(400, 300)` | 200×200 프레임을 800×600으로 표시하여 여백 없이 화면 전체를 채운다. |
| 게임오버 이미지 | 800×600, 중심 `(400, 300)` | 배경 위에 800×600으로 표시하여 화면 전체를 채운다. |
| 미로 | 400×400, 중심 `(300, 300)` | 기존 범위 `x=100~500`, `y=100~500`을 유지한다. |
| 통로·벽·도착점 | 한 칸 `cell×cell` | `cell = 400 / 미로 크기`로 계산하고 각 칸 중앙에 비율 유지하여 표시한다. |
| 미로 캐릭터 | `cell * 0.8` 정사각형 영역 | 6×6 미로는 약 53.3×53.3이다. 기존 70%에서 80%로 키우는 것을 기준으로 한다. |
| 벽 파괴 횟수 이미지 | `cell * 0.55` 정사각형 영역 | 칸 중앙에 비율 유지하여 표시한다. 숫자는 별도 글꼴로 그려 작은 크기에서도 읽을 수 있게 한다. |
| 전투·결과 화면 이미지 | 해당 화면에서 정한 표시 영역 | 공격·이펙트·결과 프레임에도 같은 비율 유지 계산을 적용한다. 위치와 영역 크기는 해당 화면 구현 시 정한다. |

- 배경·게임오버 이미지는 사용자 지정에 따라 정사각형 프레임도 800×600으로 늘려 화면을 꽉 채운다.
- 캐릭터 150×150px 프레임을 약 53~80px로 줄이면 세부 묘사는 사라질 수 있다. 캐릭터는 해당 표시 크기에서 윤곽과 표정을 확인하고, 필요하면 작은 크기용 그림을 준비한다.
- 이 절은 구현 기준을 기록한 것이다. 문서 수정만으로 실행 코드나 PNG 파일이 변경되지는 않는다.

## 결과 — `resources/result_800x400.png`
- **2행 × 4열** 시트.

| 위치 | 1열 | 2열 | 3열 | 4열 |
| --- | --- | --- | --- | --- |
| 1행 | 기준점수 미만 점수 표시 | 기준점수 근접 점수 표시 | 기준점수 초과 점수 표시 1 | 기준점수 초과 점수 표시 2 |
| 2행 | 최초 1초 공통 애니메이션 | 기준점수 미만 후속 애니메이션 | 기준점수 근접 후속 / 초과 애니메이션 1 | 기준점수 초과 애니메이션 2 |

- **1행 점수 표시**: 기준점수보다 낮으면 1열, 기준점수에 근접하면 2열을 사용한다. 기준점수보다 높으면 3열과 4열을 **같은 위치에서 1초씩 번갈아 계속 표시**한다.
- **2행 결과 애니메이션**: 처음 1초 동안 1열을 공통으로 표시한다. 이후 기준점수보다 낮으면 2열, 기준점수에 근접하면 3열을 표시한다. 기준점수보다 높으면 3열과 4열을 **같은 위치에서 1초씩 번갈아 표시**한다.
- 2행 3열은 기준점수 근접 시의 후속 표시와 기준점수 초과 시의 교대 애니메이션에 함께 사용한다.
- 기준점수의 값, 근접 판정 범위, 기준점수와 정확히 같은 경우의 분류는 미정이다.
- 위에 명시된 재생 규칙을 우선 적용하며, 명시되지 않은 속도와 반복 여부는 별도로 정한다.

## 코드 연결 계획
- `codes/maze.py`: 미로 시트의 통로·벽·벽 파괴 필요 횟수 이미지를 사용한다.
- `codes/character.py`: 이번 미로 구현에서는 캐릭터 시트 **위에서 1행 1~2열**을 사용한다. 두 프레임의 전환 조건은 구현 시 정한다.
- 캐릭터의 IDLE·회피·피격 이미지는 향후 전투 구현용으로 위치 정보를 보존한다.
- `BulBreak.py`: 화면 초기화 후 시트를 로드하여 필요한 모듈에 전달한다. 매 프레임 파일을 다시 읽지 않는다.
- 입구·출구는 지정된 이미지가 없으므로 별도 표식으로 표시한다. 미로의 통로·벽·입구·출구는 반드시 유지한다.
- 이번 미로 구현 계획에는 게임오버 시스템이 포함되지 않으므로, 게임오버 이미지는 위치만 기록하고 발생 조건을 임의로 추가하지 않는다.
