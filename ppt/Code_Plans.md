# Python 파일별 구현 계획

## 첫 게임 시작 튜토리얼
- 시작 화면에서 처음 게임을 시작하면 미로 이동·벽 파괴·출구, 전투의 교대 공격·상하 회피, 고양이 제약 예시를 방향키로 차례로 익힌다.
- 실제 미로·전투 규칙과 자원을 사용하되 연습 중에는 시간으로 체력을 잃지 않는다. 단계마다 강조 영역 밖을 검은색 알파 0.7로 덮는다.
- 고양이 예시를 끝내면 이 작업 폴더에 완료를 기록하고 일반 게임을 새로 시작한다. 완료 전에 종료하면 다음 게임 시작에 다시 열린다.

## 가이드 페이지
- 기본 조작 두 페이지는 위쪽에 ↑, 아래 줄에 ←·↓·→를 키 모양으로 그리며 각 키의 역할을 크게 강조한다. 키 아래에서 이동·벽 파괴와 공격·회피 판정의 세부 규칙을 설명한다.
- 가이드에 들어갈 때마다 1페이지로 열고 위·아래로 이전·다음 페이지를 본다. 처음과 끝에서 멈추며 오른쪽으로 시작 화면에 복귀한다.
- 1페이지는 미로, 2페이지는 전투의 기본 조작을 설명한다. 3페이지부터 제약당 한 페이지에 실제 제약 제목과 1~2줄 요약을 표시한다.

## 게임오버 선택 메뉴
- 시작 화면의 아래 두 패널 위치에 다시시작, 돌아가기를 표시하고 처음에는 다시시작을 선택한다. 위·아래로 선택하고 왼쪽으로 실행한다.
- 일반 게임은 현재 미로·전투를 다시 시작하거나 시작 화면으로 돌아간다. 디버그 한 판은 같은 제약으로 다시 시작하거나 디버그 목록으로 돌아간다.

## 미로 도착·전투 타격 GO 효과음
- 미로에서 출구에 진입하는 순간과 전투에서 적 체력 칸을 줄이는 공격 성공 순간에 기존 GO 효과음을 재생한다.
- 리듬지옥에서는 첫 패턴의 마지막 박자를 포함해 공격 성공 효과음을 재생하지 않는다. 박자 안내 박수는 유지한다.

## 리듬 전투 시작 카운트다운
- 첫 패턴의 마지막 박자를 놓치고 전투가 계속되면 판정 시간이 끝났을 때 기존 GO 전환음을 재생한다.
- 두 번째 시범과 효과음이 겹칠 때만 시범을 늦춰 GO 이후 최소 0.16초를 확보한다.
- 리듬 전투 진입마다 `3 → 2 → 1 → GO`를 각각 0.625초씩 표시한다. 글자는 단계마다 조금 커졌다가 줄어들고, GO가 끝나면 첫 시범 박자를 시작한다.
- 카운트다운 중 입력·누락·시범 박수는 대기한다. GO에 짧은 전구 파열음과 유리 잔향을 한 번 재생하며 박수보다 작게 설정한다.

## 시작 화면 세로 선택 메뉴 및 글꼴
- `Main.png`를 왼쪽 위에 두고, 오른쪽 아래에 `Menu.png`로 게임시작·가이드·디버그모드·게임종료를 쌓는다. 오른쪽 경사는 화면 밖에 두며 선택 항목은 노란색으로 왼쪽에 돌출한다.
- 시작 화면은 게임시작을 기본 선택한다. 위·아래로 항목을 고르고 왼쪽으로 실행한다. 디버그에서는 위·아래로 제약을 고르고 왼쪽으로 플레이하며, 가이드와 디버그에서 오른쪽으로 복귀한다.
- 게임에서 직접 그리는 글자는 공게임즈 공식 이사만루체를 사용한다. 시작·디버그 목록의 조작과 실제 렌더링을 검증한다.

## Menu.png 기반 시작 메뉴와 HUD
- `main.py`에서 메뉴 이미지를 공유한다. `menu_modes.py`는 시작 메뉴에서만 기존 글자 배경을 이미지 패널로 바꾼다.
- `hud.py`는 왼쪽 체력과 통합 오른쪽 패널을 표시한다. 타이머는 현재 게임오버 판정의 남은 시간을 사용하고 리듬, 도착 확인, 전환 안내, 게임오버 등 정지 구간은 흰색으로 채운다.
- `battle.py`는 현재 성공 목표에 연동한 적 체력 칸을 표시한다. 미로·전투의 하단 안내와 활성 제약의 오른쪽 정보는 숨기고 기존 전환 제목과 게임오버 조작을 유지한다.

## 시작 화면 방향별 메뉴
- `main.py`에서 `resources/Main.png`를 불러오고, `menu_modes.py`에서 원본 비율로 화면 가운데에 표시한다.
- 이미지 위는 종료, 아래는 게임 시작, 왼쪽은 가이드, 오른쪽은 제약 한 판 메뉴를 표시한다. 기존 방향키 연결을 사용한다.

## 고양이 제약 구현
- `constraints.py`에서 공통 단일 제약 추첨 및 제목 전용 전환 안내를 처리한다. `menu_modes.py`에는 미로·전투 연습을 각각 등록한다.
- `cat_constraint.py`에서 `manja-vitolic-gKXKBY-C-Dk-unsplash.jpg`와 `girl-with-red-hat-x170FVylLLg-unsplash.jpg`에서 배경을 제거한 PNG를 사용해 각각 배경과 오브젝트를 그린다.
- `game_framework.py`는 활성화된 미로·전투에서만 배경 → 게임 화면 → 고양이 오브젝트 순으로 렌더링한다. 안내 화면과 다른 제약에서는 효과를 종료하고 다음 적용 시 새로 배치한다.
- 제약 한 판의 고양이 미로는 출구 1회, 전투는 기존 성공 목표를 기준으로 종료한다.

## 제약 한 판 플레이
- 시작 화면에서 오른쪽으로 제약 선택 화면에 진입한다. 오른쪽은 다음 제약, 왼쪽은 시작 화면, 아래는 선택한 제약 시작이다.
- 중앙 출구, 전투 기본, 리듬, 미로·전투 고양이 제약을 각각 고른다. 미로는 한 번 탈출하면 끝나고, 전투는 해당 모드의 성공 목표를 사용한다.
- 클리어하거나 게임오버가 되면 같은 제약이 선택된 화면으로 돌아온다. 각 판은 체력과 점수를 새로 시작한다.

## 리듬 2패턴 및 단일 제약 무작위 선택
- 리듬 시작마다 저장된 패턴 중 서로 다른 2개를 무작위로 선택하고 두 패턴의 박자 합계를 성공 목표로 표시한다.
- 제약 안내마다 진입 모드에 맞는 제약 중 1개를 무작위로 선택한다. 안내 종료 후 이전 제약을 교체하여 선택한 1개만 적용한다.
- 안내와 플레이 패널에는 실제 선택된 제약의 이름과 설명을 표시한다. 기존 첫 전투 전 제약 미적용 규칙을 유지한다.

## 리듬 전체 박자 클리어 목표
- rhythm 제약의 성공 목표는 resources/rhythm_hell 전체 구간의 hits 개수 합계로 정한다. 일반 전투는 기존 10회를 유지한다.
- 성공 목표와 화면 표시를 함께 변경하며, 박자 실패·누락 피해 및 네 방향키 공통 판정은 유지한다.

## 리듬 방향키 공통 판정
- 리듬 제약에서는 네 방향키 모두 박자만 판정하며, 성공 입력은 교대 공격과 성공 횟수 증가로 연결한다.
- 적 방향 불일치 피해를 적용하지 않고 기존 박자 실패·누락 피해와 방향 FIFO 진행은 유지한다.

## 이전 미로 제약 계획 — 도착 화면 확인 (제거됨)
- [미로] 도착 화면 확인 제약이 활성화된 상태에서 도착점에 도달한 뒤 다음 미로로 넘어가는 경우, `maze` 시트 1행 4열 이미지를 지정된 플레이 화면 영역에 출력한다.
- 도착 화면에서 아무 방향키나 새로 한 번 누르면 캐릭터를 이동시키지 않고 다음 미로로 전환한다. 도착점에 도달할 때 사용한 입력은 확인 입력으로 사용하지 않는다.
- 미로에서 전투로 넘어가는 경우에는 이 도착 화면과 방향키 확인 단계를 적용하지 않는다.
- 미로의 통로·벽·입구·출구 및 방향키 전용 조작을 유지한다. 전투의 실시간 행동과 적 행동 큐도 유지한다.
- 첫 전투 → 미로 안내 종료 시 `maze_arrival` 제약을 획득한다. 활성 제약 set에 이 제약이 있을 때만 도착 화면을 표시하며, 없으면 자동 전환한다. 누적 규칙은 `Constraint_Plan.md`를 따른다.

## 최신 전투 수정 및 코드 상단 안내
- `codes/battle.py`: 적 가로공격 시 좌우 어느 입력도 성공 횟수를 올리고 해당 방향 공격 모션을 재생한다. 이전 실패 회전도 해제한다.
- 적 첫 프레임 0.36초와 주인공 기존 속도를 유지한다. 코드·테스트 상단에서 `AI_Planner.md`와 이 문서의 작성·커밋 기준을 안내한다.
- 전체 자동 검증 46개 통과. 최신 기준은 기존의 가로공격 패링 대기 표시·공격 순서 실패 규칙보다 우선한다.

## 임시 작업 기록 — 미로 주파 타이머와 전투 무행동 타이머 분리
- 미로는 고정 3초 주파 타이머를 사용한다. 입력으로 회복하지 않고 다음 미로에서 3초로 초기화하며 최대 시간 감소는 적용하지 않는다.
- 3초 소진마다 체력 1을 감소시키고 다시 3초를 센다. 체력 소진 시 게임오버이며 기존 15초 강제 종료도 유지한다.
- 전투는 기존 무행동 타이머·입력 시 1초 회복·피격 시 0.5초 차감을 유지한다. 전투 플레이 자체는 아직 미구현이다.
- 이 기록은 이전의 미로 최대 시간 감소와 입력 회복 설명보다 우선한다.

## 임시 정정 기록 — 상단 큰 정보 영역 테두리
- 체력·타이머 상단 영역과 오른쪽 위 점수·진행 순서 영역에는 큰 흰색 테두리를 각각 하나씩 표시한다.
- 글자별 테두리는 표시하지 않고 제약시스템 패널의 기존 테두리는 유지한다.

## 임시 작업 기록 — 제약시스템 테두리만 유지
- 글자별 테두리와 체력·타이머·점수·진행 순서 영역의 테두리를 제거한다.
- 검정 배경과 흰색 글자를 유지하고 오른쪽 제약시스템 패널만 흰색 테두리를 표시한다.

## 임시 작업 기록 — 플레이 정보 테두리
- 플레이 정보 패널과 글자 배경은 검정색을 유지하고 테두리는 흰색으로 표시한다.

## 임시 작업 기록 — 플레이 정보 배경 검정색 적용
- 플레이 중 표시하는 체력·타이머·점수·진행 순서·제약 패널과 안내 글자 배경을 검정색으로 변경한다.
- 검정 배경의 글자는 흰색으로 표시한다. 시작 화면과 가이드의 흰색 배경은 유지한다.

## 임시 작업 기록 — 미로 PNG 투명화 원복
- 미로 원본·실행용 PNG 두 개만 투명화 직전 파일로 복원한다. 다른 PNG의 투명화와 검정 화면 배경은 유지한다.

## 임시 작업 기록 — 검정 배경
- 전체 화면 배경을 #000000으로 채운 뒤 모드와 UI를 그린다. 기존 미로 타일의 전체 화면 확대 배경은 제거한다.

## 임시 작업 기록 — PNG 검정색 투명화
- resources의 PNG 10개에서 RGB가 정확히 #000000인 픽셀만 알파값 0으로 바꾼다.
- 이미지 크기와 시트 배치, 다른 색상 및 기존 투명도는 유지한다. 원본·실행용 시트에 모두 적용한다.
- 검정에 가까운 색은 변환하지 않으며 그림 내부의 순수 검정도 변환 대상이다.
- 변환 완료: PNG 10개. 저장 후 전체 픽셀 재검사로 순수 검정 알파 0 및 다른 픽셀·해상도 보존 확인. 게임 자동 검증 24개 통과.

## 임시 수정 기록 — 미로 크기와 표시
- 현재 플레이 경로는 6×6이며 4×4 미로 생성 호출은 없다. 출구 제외 영역의 4×4 계산은 미로 크기가 아니므로 유지한다.
- 미로 생성은 6×6만 허용하고, 흰색 격자선과 흰색 벽 파괴 횟수 숫자를 표시한다.
- 출발점·출구의 IN·OUT 글자와 관련 안내를 제거한다. 출발 좌표와 출구 이미지·판정은 유지한다.
- 이 기록은 앞선 미로 격자선 제거 기록보다 우선한다.
- 수정 완료: 6×6 제한, 흰색 격자·숫자, IN·OUT 글자 제거. 자동 검증 24개 통과.

## 임시 정정 기록 — 플레이 영역과 정보 영역 구분
- 미로·전투 플레이 영역에는 코드 생성 직사각형이나 격자선을 그리지 않는다.
- 그 밖의 체력·타이머·점수·진행 순서·제약 정보 영역은 흰색 패널과 글자 배경을 표시한다.
- 점수의 오른쪽 위 배치와 `미로 → 미로 → 전투` 문구를 유지한다.
- 이 정정은 아래의 게임 화면 전체 도형 제거 기록보다 우선한다.

## 임시 수정 기록 — 게임 화면 리소스 표시
- 게임 화면의 코드 생성 직사각형(패널·글자 배경·격자선)을 제거하고 기존 resources 이미지를 유지한다.
- 오른쪽 위에 점수를 표시하며, 점수 산정 규칙은 미정이므로 초기값 0만 준비한다.

- 이 기록은 아래의 흰색 패널 구현 설명보다 우선한다.

## 제약시스템 공통 규칙 — 최신 확정 사항
- 제약시스템이 동작하는 동안에도 게임오버 시스템은 동작한다. 이를 위해 **일반 게임오버 시스템과 별도로 제약시스템 전용 게임오버 시스템을 만든다.**
- 미로 ↔ 전투의 일반 전환 중에는 기존 게임오버 금지 규칙을 유지한다. 단, 전환 중 제약시스템이 동작하는 구간에는 제약시스템 전용 게임오버 판정을 적용한다.
- 전용 게임오버의 구체적인 발생 조건, 타이머·체력 사용 여부는 아직 미정이며 임의로 확정하지 않는다.
- 제약 안내는 아이작처럼 **왼쪽에 제약 관련 그림, 오른쪽에 짧은 설명글**을 배치한다.
- 설명글은 **최대 2줄**, **각 줄은 최대 4문장**으로 제한하고 짧게 작성한다. 자동 줄바꿈을 포함한 실제 표시도 2줄을 넘지 않게 한다.
- 기존 제약 안내 시간 약 1~2초와 방향키 전용 조작을 유지한다. 미로의 통로·벽·입구·출구, 전투 주인공의 실시간 행동과 적의 행동 큐도 유지한다.
- 이 규칙은 기존 문서의 제약시스템 관련 게임오버 금지·예외 설명보다 우선한다. 현재는 기획 반영이며 코드 구현 완료를 뜻하지 않는다.



사용자가 Python 파일에 작성한 계획 주석을 정리한 문서다. 구현 완료를 뜻하지 않는다. 원본 계획 주석은 작업 파일에 보존하되 커밋에서 제외한다. 이 문서와 구현 변경은 기능별로 작게 나누어 한글로 커밋한다. 자세한 규칙은 [AI_Planner.md](AI_Planner.md)를 따른다.

## 게임오버 선택 및 작업 단위 — 최신 확정 사항
- 게임오버 기준은 동시에 적용하지 않고 새 게임·재시작마다 하나를 무작위로 지정한다. 현재 추첨 대상은 1번·2번이며, 3번은 추첨에서 제외한다.
- 선택한 기준은 연속 미로 진행 중 유지한다. 1번은 무행동 타이머만, 2번은 체력 규칙만 적용한다. 15초 강제 종료는 3번 전용이며 현재 플레이에서는 적용하지 않는다.
- 게임 화면 위쪽에 선택된 게임오버 기준과 해당 타이머·체력 정보를 표시한다. 가이드 설명은 한글로 작성한다.
- 작업은 Markdown에 먼저 기록하고 커밋한 후 코드를 수정한다. 코드 커밋은 파일별로 나누고, 각 커밋의 추가·삭제 합계는 최대 20줄로 제한한다.
- 이 절은 이전의 동시 적용·공통 15초 제한 설명보다 우선한다.
## 적 패턴 큐 구현 기준 — 최신 확정 사항
- `horizontal_attack_parry`는 매 입력에서 적 가로 공격과 좌우 입력의 방어 성공을 확인한다. 공격·패링 동시 조건이면 캐릭터 시트 4행 1~4열을 반복하고 공격 시트를 사용하지 않는다. 공격 순서의 정답 여부와 관계없이 동일한 행을 사용하며 다음 입력에서 조건을 다시 계산한다.
- 공격 순서가 틀렸지만 방어 방향을 맞춘 경우에는 방어 성공으로 판정하되 **`player_state='idle'`, `visual_state='idle'`**로 전환해 IDLE 애니메이션을 반복한다. 임시 `guard` 표시는 사용하지 않는다. 공격 시트·공격 이펙트·피격 시트는 재생하지 않고 실패 이펙트와 회전은 유지한다.
- `GameOverRules.record_wrong_defense(health_damage=1)`을 적의 위·아래 공격 방어 실패에 적용한다. 체력 1과 타이머 0.5초를 차감하고 체력 0이면 게임오버다. 가로 방어 실패의 체력 직접 차감은 추가하지 않는다.
- **공격 순서 보정**: 기존에는 같은 방향 반복도 성공했으나, 이제 `next_attack_direction`을 왼쪽으로 시작해 성공 시에만 반대로 전환한다. 회피와 실패는 순서·성공 횟수를 보존한다. 적 방향 FIFO와 별도 상태이다.
- `Assets.yellow_arrow_sheet`는 `resources/effect_arrows_yellow.png`를 로드한다. 왼쪽 공격은 주인공 왼쪽에, 오른쪽 공격은 주인공 오른쪽에 노란 화살표로 안내한다. 적의 준비 방향은 빨간 화살표로 표시한다.
- 노란 화살표와 주인공 사이의 여백을 약 절반으로 줄이고, 노란 화살표의 알파값은 0.85로 표시한다.
- 실패 반응은 이펙트 시트 1행 2열 0.4초 표시와 주인공의 오른쪽 15도 기울기·복귀 0.6초로 구성한다. `draw_frame`의 선택적 회전 인수로 주인공만 회전하며 입력 처리는 계속한다.
- **임시 전투 연결 완료**: `codes/battle.py`에서 실시간 공격·회피·패링·피격, 성공 누적 10회 클리어를 처리한다. 실패는 이번 성공 증가만 취소하며 기존 성공 횟수를 보존한다. 빠른 공격 입력도 집계하고 15초 제한은 유지한다.
- `codes/maze_gamemode.py`는 두 번째 미로 출구에서 전투로 전환한다. 전투 클리어 시 미로 두 번을 다시 시작하고 체력·점수는 유지한다.
- `codes/gameover.py`의 `animation_frame_seconds`가 기본 0.15초(최대 타이머에 따라 0.075~0.15초) 간격을 제공하고, `codes/animation.py`가 경과 시간으로 프레임을 선택한다. 미로처럼 빠른 반응을 위해 적 단계와 주인공 동작은 매 새 입력에 즉시 반영하며 재생 종료 대기를 없앴다.
- 전투 애니메이션 배치는 `animation_place.md`의 공격 이펙트·적 시트 절을 따른다. `effect_attack_800x200.png`는 주인공 공격에 1~2열, 적 공격에 3~4열을 순서대로 사용한다.
- `enemy_animation_600x600.png`는 1행 가로·2행 위·3행 아래 공격이며, 준비는 1~2열, 공격은 3~4열이다. 비행동 시에는 4행 1~4열을 순서대로 반복한다.

## 어두ComCom과 건물부수기
- 어두ComCom은 주인공 칸 중심에서 반지름 1.5칸의 원만 보이도록 미로를 가린다. 어두ComCom의 게임오버 타이머 최대치는 4초로 설정한다.
- 건물부수기는 적 대신 Menu.png를 쌓은 3~5층 건물이 중력으로 떨어지는 전투다. 주인공 머리와 건물 밑면이 맞닿을 때 좌우 어느 쪽으로도 맨 아래층을 공격하고, 층마다 10회 타격하면 부서진다.
- 건물부수기에서 좌우 방향키는 건물 내구도를 깎았을 때만 게임오버 타이머를 회복한다. 위 방향키의 타이머 회복은 기존과 같다.
- 건물의 낙하와 띄우기는 기존과 같은 높이까지 움직이되 두 배의 시간이 걸린다.
- 위 방향키는 맨 아래층과 주인공 머리 사이가 0~10픽셀이면 건물을 띄우고, 건물이 떨어져 있으면 바닥에서 주인공을 점프시킨다. 공격·점프에는 기존 전투 시트를 사용한다.
- 내구도 글자는 건물 왼쪽에 표시한다. 주인공의 자유 점프는 건물이 튕겨 오르는 높이보다 높다. 밑면에 닿으면 약 0.45초 동안 건물과 같이 움직인다. 이후 평소 건물 낙하의 약 2.2배 속도로 떨어지며, 건물이 정지하거나 상승 중이면 최소 낙하 속도로 이탈한다.
- 공중에서 밑면에 부딪히는 순간에는 짧은 충돌 표시와 기존 피격 모션을 사용한다. 충돌 연출로 체력이 줄지는 않는다.
- 건물을 튕겨 올리거나 공중에서 밑면에 부딪히는 순간 기존 전구 파열음을 한 번 재생한다.
- 바닥에 서 있을 때 건물 밑면이 피격 범위 안으로 20픽셀 내려오면 체력 1을 잃고 맨 아래층이 부서진다. 남은 건물은 낙하 속도를 0으로 줄이고 0.6초 동안 평소의 35% 가속도로 떨어진다.

## 미로 제약 봄버맨
- 미로 시작 시 서로 다른 통로 네 곳을 정하고, 시작 직후·0.2초·0.4초·0.6초에 폭탄과 해당 십자 범위를 순차 표시한다. 벽과 관계없이 각 폭탄의 가로·세로 줄 전체가 폭발 범위이며, 주인공 주변에 대피 가능한 통로를 최소 한 곳 남겨 둔다.
