## 임시 작업 기록 — PNG 검정색 투명화

## 임시 수정 기록 — 미로 크기와 표시

- 미로 생성은 6×6만 허용하고, 흰색 격자선과 흰색 벽 파괴 횟수 숫자를 표시한다.
- 출발점·출구의 IN·OUT 글자와 관련 안내를 제거한다. 출발 좌표와 출구 이미지·판정은 유지한다.
- 이 기록은 앞선 미로 격자선 제거 기록보다 우선한다.
- 수정 완료: 6×6 제한, 흰색 격자·숫자, IN·OUT 글자 제거. 자동 검증 24개 통과.

## 임시 작업 기록 — 화면 UI 및 게임오버 개편
- 구현 완료: 오른쪽 흰색 제약 패널(미로와 같은 높이), 상단 진행 순서 `미로 → 미로 → 전투`.
- 구현 완료: 상단 왼쪽 2/3 체력 표시. 이펙트 1행 1열은 남은 체력, 1행 2열은 소진 체력이며 오른쪽부터 소진한다.
- 구현 완료: 글자 뒤에는 검은 테두리의 반투명 흰색 배경, 기본 글자는 검은색으로 표시한다.
- 구현 완료: 체력 3과 무행동 타이머를 함께 사용하며 소진마다 체력 1 감소 후 타이머를 다시 센다.
- 구현 완료: 다음 미로에서 최대 시간이 0.05초씩 감소(최소 1초), 입력마다 1초 회복, 15초 제한 문구 갱신.
- 전투는 안내 상태를 유지하며 순서 표시는 기획 안내다. 제약 전용 게임오버의 미정 조건은 추가하지 않는다.
- 문서 선행 커밋 후 코드·검증을 파일별 추가·삭제 합계 20줄 이내의 한글 분류 커밋으로 기록했다.
- 변경 파일: `codes/hud.py`, `gameover.py`, `maze_gamemode.py`, `game_framework.py`, `main.py`, `maze.py`, `menu_modes.py`, `guide_mode.py` 및 회귀 검증.
- 검증: 자동 검증 22개 및 실제 pico2d 화면 렌더링 확인. 체력 2개와 소진 이미지 1개, 패널 배치와 글자 배경을 확인했다.
- 전환 시 남은 시간은 새 최대 시간 이내로 유지한다. 소진 후 다음 주기를 시작하며 체력 0이면 게임오버다.
- 이 임시 기록의 통합 체력·타이머 규칙은 아래의 과거 무작위 기준 선택 설명보다 우선한다.

## 제약시스템 공통 규칙 — 최신 확정 사항
- 제약시스템이 동작하는 동안에도 게임오버 시스템은 동작한다. 이를 위해 **일반 게임오버 시스템과 별도로 제약시스템 전용 게임오버 시스템을 만든다.**
- 미로 ↔ 전투의 일반 전환 중에는 기존 게임오버 금지 규칙을 유지한다. 단, 전환 중 제약시스템이 동작하는 구간에는 제약시스템 전용 게임오버 판정을 적용한다.
- 전용 게임오버의 구체적인 발생 조건, 타이머·체력 사용 여부는 아직 미정이며 임의로 확정하지 않는다.
- 제약 안내는 아이작처럼 **왼쪽에 제약 관련 그림, 오른쪽에 짧은 설명글**을 배치한다.
- 설명글은 **최대 2줄**, **각 줄은 최대 4문장**으로 제한하고 짧게 작성한다. 자동 줄바꿈을 포함한 실제 표시도 2줄을 넘지 않게 한다.
- 기존 제약 안내 시간 약 1~2초와 방향키 전용 조작을 유지한다. 미로의 통로·벽·입구·출구, 전투 주인공의 실시간 행동과 적의 행동 큐도 유지한다.
- 이 규칙은 기존 문서의 제약시스템 관련 게임오버 금지·예외 설명보다 우선한다. 현재는 기획 반영이며 코드 구현 완료를 뜻하지 않는다.



사용자가 Python 파일에 작성한 계획 주석을 정리한 문서다. 구현 완료를 뜻하지 않는다. 원본 계획 주석은 작업 파일에 보존하되 커밋에서 제외한다. 이 문서와 구현 변경은 기능별로 작게 나누어 한글로 커밋한다. 자세한 규칙은 [AI_Planner.md](AI_Planner.md)를 따른다.

## 공통 구현 방식

- 진입점과 메인 모듈의 지정에 따라 pico2d는 `from pico2d import *`로 불러온다.
- 두 파일의 지정에 따라 상태 머신은 `transitions`를 사용한다.
- 기존의 통로·벽·입구·출구, 방향키 전용 조작, 모드 전환 중 게임오버 금지 규칙을 유지한다.

## 구현 전에 확인할 내용

- 메인 루프 위치: `BulBreak.py` 주석은 해당 파일에 루프를 두라고 하지만 `codes/main.py` 주석은 루프를 옮기고 진입점에는 캔버스 관리만 남기라고 한다. 이번 적용에서는 메인 루프를 `codes/main.py`에 두고 진입점은 캔버스 관리와 실행 연결을 맡는 구성으로 진행했다.
- 게임오버의 세 번째 기준은 기준 기획서에도 아직 비어 있다. 조건을 임의로 만들지 않는다.
- 시작·설명·종료 모드와 전투·적의 세부 동작은 상단 주석만으로 확정하지 않는다.

## 기능별 커밋 단위

다음은 작업 분할안이다. 한 화면에서 검토하기 어려울 만큼 커지면 독립적으로 확인 가능한 단계로 더 나눈다.

1. 메인 루프 위치 확정 후 진입점과 메인 루프 분리.
2. 프레임워크의 현재·이전 모드 관리와 초기화 구성.
3. 모드 전환 연결. 각 모드 연결도 별도 기능으로 확인하고 커밋.
4. 미로 판정을 미로 모드와 연결.
5. 캐릭터 이동 상태와 애니메이션 연결.
6. 캐릭터 벽 공격 상태와 애니메이션 연결.
7. 게임오버 판정 분리. 확정된 조건 하나씩 확인하고 커밋.
8. 전투 상태·전투·적은 상세 계획 확정 후 기능별로 구현.

커밋 제목은 기존의 `애니메이션 계획 추가`, `게임 개발 계획 작성(미로)`처럼 변경 대상과 작업을 짧은 한글로 적고 필요하면 괄호로 범위나 예외를 덧붙인다.

## 15초 강제 종료 및 화면 규칙 — 구현 완료
- `codes/game_framework.py`에서 미로·전투 진입마다 0~15초의 독립 타이머를 관리한다. 새 미로 진입과 재시작 시 초기화하며 일반 입력으로 연장하지 않는다. 메뉴·가이드에서는 동작하지 않는다.
- 15초 도달 시 게임오버 처리하고 큰 흰색 한글로 “그냥 다른게임하러가세요”를 표시한다. 기존 타이머·체력으로 먼저 게임오버가 되면 기존 게임오버를 유지한다. 아래는 재시작, 위는 시작 화면 복귀다.
- 시작 화면 글꼴은 별도 지시가 없으면 흰색이다. 구분이 필요하면 검은색 계열을 제외한 색을 사용할 수 있다.
- 시작 화면 왼쪽은 `codes/guide_mode.py`의 가이드로 진입하고 가이드 오른쪽은 시작 화면으로 복귀한다.

## 게임오버 선택 및 작업 단위 — 최신 확정 사항
- 게임오버 기준은 동시에 적용하지 않고 새 게임·재시작마다 하나를 무작위로 지정한다. 현재 추첨 대상은 1번·2번이며, 3번은 추첨에서 제외한다.
- 선택한 기준은 연속 미로 진행 중 유지한다. 1번은 무행동 타이머만, 2번은 체력 규칙만 적용한다. 15초 강제 종료는 3번 전용이며 현재 플레이에서는 적용하지 않는다.
- 게임 화면 위쪽에 선택된 게임오버 기준과 해당 타이머·체력 정보를 표시한다. 가이드 설명은 한글로 작성한다.
- 작업은 Markdown에 먼저 기록하고 커밋한 후 코드를 수정한다. 코드 커밋은 파일별로 나누고, 각 커밋의 추가·삭제 합계는 최대 20줄로 제한한다.
- 이 절은 이전의 동시 적용·공통 15초 제한 설명보다 우선한다.
