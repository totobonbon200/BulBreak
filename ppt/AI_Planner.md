# 미로 구현 계획

## 제약시스템 공통 규칙 — 최신 확정 사항
- 제약시스템이 동작하는 동안에도 게임오버 시스템은 동작한다. 이를 위해 **일반 게임오버 시스템과 별도로 제약시스템 전용 게임오버 시스템을 만든다.**
- 미로 ↔ 전투의 일반 전환 중에는 기존 게임오버 금지 규칙을 유지한다. 단, 전환 중 제약시스템이 동작하는 구간에는 제약시스템 전용 게임오버 판정을 적용한다.
- 전용 게임오버의 구체적인 발생 조건, 타이머·체력 사용 여부는 아직 미정이며 임의로 확정하지 않는다.
- 제약 안내는 아이작처럼 **왼쪽에 제약 관련 그림, 오른쪽에 짧은 설명글**을 배치한다.
- 설명글은 **최대 2줄**, **각 줄은 최대 4문장**으로 제한하고 짧게 작성한다. 자동 줄바꿈을 포함한 실제 표시도 2줄을 넘지 않게 한다.
- 기존 제약 안내 시간 약 1~2초와 방향키 전용 조작을 유지한다. 미로의 통로·벽·입구·출구, 전투 주인공의 실시간 행동과 적의 행동 큐도 유지한다.
- 이 규칙은 기존 문서의 제약시스템 관련 게임오버 금지·예외 설명보다 우선한다. 현재는 기획 반영이며 코드 구현 완료를 뜻하지 않는다.



## 작업 및 커밋 규칙 — 이후 작업에도 반드시 적용
- 프로그래밍을 제외한 모든 작업은 한글로 진행한다. 대화, 작업 설명, 계획, 문서, 검토 결과, 커밋 제목과 본문에도 적용한다. 프로그래밍에 필요한 코드·식별자·명령어·파일명 등은 원래 표기를 유지할 수 있다.
- 유지보수를 위해 기능 하나를 구현하거나 수정할 때마다 확인 후 바로 커밋한다. 여러 기능을 한 번에 모아 커밋하지 않는다.
- 변경 내용이 한 화면에서 검토될 정도로 작게 나누고 자주 커밋한다. 한 기능이 커지면 독립적으로 확인 가능한 단계로 나눠 커밋한다.
- 커밋 제목과 본문은 모두 한글로 작성한다. 파일명·코드 식별자 등은 필요한 경우 원래 표기를 유지한다.
- 커밋 전 `git log`로 사용자가 작성한 최근 제목을 확인하고 기존 문체를 따른다. 짧게 변경 대상과 작업을 적고, 필요한 범위나 예외는 괄호로 덧붙인다.
- 기존 제목 참고: `애니메이션 계획 추가`, `게임 개발 계획 작성(미로)`, `리소스 추가 및 애니메이션 위치 추가(적, 제약 X)`.
- 커밋에는 해당 기능의 파일과 변경 부분만 포함한다. 사용자가 작업 중인 다른 변경이나 자동 생성 파일을 함께 넣지 않는다.
- Python 파일 상단에 사용자가 작성한 `#` 계획은 `ppt/Code_Plans.md`에 정리하며, 원문에 없는 계획을 임의로 확정하지 않는다.
- 이후 AI 작업을 시작할 때 이 규칙과 파일 상단의 최신 계획을 확인한다. 파일 상단 계획이 바뀌면 계획 문서도 함께 갱신한다.

- 사용자가 Python 파일에 작성한 계획용 `#` 주석 자체는 커밋에 포함하지 않는다. 작업 파일에는 그대로 보존하고 구현 변경과 섞이면 부분 스테이징 후 차이를 확인해 제외한다. 파일 전체 추가나 `git add .`로 섞어 넣지 않는다. 계획을 정리한 Markdown 문서는 커밋 대상으로 관리한다.

## 파일별 계획 적용 현황 — 이전 임시 구현 설명보다 우선
- `BulBreak.py`는 캔버스 열기·닫기와 실행 연결, `codes/main.py`는 자원 로드와 메인 루프를 맡는다. 모드 관리는 `codes/game_framework.py`의 `transitions` 상태 머신을 사용한다.
- 현재·이전 모드와 최초 진입 여부를 관리한다. 시작 화면의 아래는 새 게임 시작, 위는 종료, 오른쪽은 설명이며 설명 화면의 왼쪽은 돌아가기다. 게임오버에서는 아래로 재시작하고 위로 시작 화면에 돌아간다. 재시작과 시작 화면에서의 새 게임은 미로·완료 횟수·체력 3·타이머 3초를 초기화한다.
- 미로 입력·진행·그리기는 `codes/maze_gamemode.py`에서 연결하고, 미로 판정은 `codes/maze.py`에 유지한다. 미로 무한 반복은 계속 유지한다.
- 캐릭터 행동은 대기·이동·벽 공격으로 분리했다. 이동과 벽 공격 모두 배치가 확정된 캐릭터 시트 1행 1~2열을 프레임당 0.15초로 사용한다. 전투용 공격 시트는 미로에 사용하지 않는다.
- `codes/gameover.py`에서 최대 3초 타이머와 체력을 관리한다. 입력마다 1초를 회복하되 최대 3초를 넘지 않는다. 미로 전환에는 타이머를 소모하지 않고 남은 시간을 유지한다.
- 체력은 3으로 시작하고 미로에 머무는 동안 3초마다 1씩 반복 감소한다. 감소할 때마다 다음 3초를 세며, 입력으로 이 체력용 타이머를 초기화하지 않는다. 새 미로 진입 시 체력용 타이머는 처음부터 센다. 체력 소진 또는 무행동 타이머 소진 시 게임오버다. 전투 방어 실패에 따른 체력 감소 인터페이스는 준비했으나 전투 연결은 미구현이다.
- 게임오버 이미지는 미로 시트 1행 4열을 불투명도 0.5로 전체 화면에 마지막으로 그린다.
- 전투·결과 모드는 전환 가능한 안내 화면만 준비했다. 기존 미로 반복을 전투로 자동 변경하지 않았다. 전투·적 상세 동작, 점수 계산, 세 번째 게임오버 조건은 미정으로 남긴다.
- 자동 검증 10개 통과(시작 조작, 재시작 초기화·누름 유지 방지, 시작 화면 복귀 후 새 게임 포함): 모드 이력·재진입, 타이머 회복·전환 보호, 미로별 체력 감소, 벽 파괴·행동 상태, 메뉴·미로·게임오버 연결. 실제 pico2d 캔버스의 자원 로드 및 반투명 그리기도 확인했다.

## 확정된 전투 게임오버 규칙 — 구현 예정
- 첫 번째 기준: 전투에서도 무행동 타이머와 입력 시 1초 회복(최대 3초)을 유지한다. 적에게 맞으면 현재 타이머에서 0.5초를 추가 차감하며, 0 이하가 되면 즉시 게임오버다.
- 두 번째 기준: 별도의 3초 타이머를 사용한다. 3초 이내로 입력하지 않거나 정확한 입력을 하지 않으면 체력을 1 감소시키고 이 타이머를 3초로 초기화한다. 첫 번째 기준의 타이머와 혼동하거나 함께 초기화하지 않는다.
- 이번 변경은 기획 문서 반영이며 전투 코드에는 아직 적용하지 않았다. 정확한 입력의 판정 조건과 정상 입력 시 두 번째 타이머 처리 방식은 추가 설명 없이 임의로 확정하지 않는다.

## 최신 임시 구현 변경 사항
- 사용자 요청에 따라 현재 시제품은 크기별 횟수 제한 없이 같은 크기의 미로를 무한 반복한다. 전투 연결 전까지 적용하는 임시 동작이며 아래의 기존 횟수 제한 계획보다 우선한다.
- 플레이어 상태는 `codes/character.py`의 `PlayerState.PLAYING`, `PlayerState.GAME_OVER`로 구분한다. `is_playing`이 참일 때만 게임 조작을 처리한다.
- 시작 또는 마지막 방향키 누름부터 3초간 입력이 없으면 게임오버 상태로 전환한다. 벽 타격과 경계 방향 입력도 행동으로 인정하지만, 키를 길게 누르는 자동 반복은 인정하지 않는다.
- 미로 전환 시 무행동 시간을 초기화하며 전환 자체로 게임오버가 발생하지 않는다. 게임오버에서는 창을 유지하고 입력을 차단하며 미로 시트 2행 4열 이미지를 표시한다.
- 게임오버는 프로그램 종료와 구분한다. 게임오버에서 아래는 재시작, 위는 시작 화면 복귀다.

## 기준과 이번 작업 범위
- 기획 기준은 `ppt/Planner_with_AI.md`이다. 이전 `AI_Plan.md`나 README와 다른 내용은 이 기준을 우선한다.
- 현재 `BulBreak.py`, `codes/maze.py`, `codes/character.py`, `codes/battle.py`는 비어 있으므로 아래 역할에 따라 구현한다.
- 이번에는 미로 생성, 방향키 이동, 벽 파괴, 출구 도달, 연속 미로 진행까지만 만든다.
- 전투, 적의 패턴 큐, 증강, 제약 시스템, 게임오버는 이번 구현에서 제외한다. 마지막 미로 이후에는 전투 연결 대기 화면만 표시한다.
- 이 문서는 구현 계획이며, 아직 Python 코드를 변경하지 않는다.

## 반드시 유지할 규칙
- 미로에는 **통로, 벽, 입구, 출구**가 반드시 존재한다. 생성과 화면 표시 모두 이 네 요소를 유지한다.
- 게임 조작은 **방향키만** 사용한다. 시작·재시작에도 별도 문자키나 마우스를 요구하지 않는다.
- 출구 도달 시 다음 단계로 자동 전환하며, 전환 때문에 게임오버가 발생하지 않는다.
- 향후 전투 연결 시 플레이어의 실시간 행동과 적의 행동 큐를 반드시 유지한다. 이번 미로 구현은 해당 구조를 대체하거나 삭제하지 않는다.
- 제약 시스템의 게임오버 예외는 구체적인 조건이 불명확하므로 이번에 임의로 구현하지 않는다.

## 미로 데이터와 생성 방식
- 좌표는 `(행, 열)`로 통일하고 왼쪽 위를 `(0, 0)`으로 한다.
- 제안하는 초기 표현은 **칸 단위 벽**이다. 각 칸은 통로 또는 파괴 가능한 벽이고, 입구·출구는 통로 위에 별도로 표시한다.
- 크기는 한 묶음을 시작할 때 4×4 또는 6×6 중 랜덤으로 고른다. 같은 크기로 각각 3회 또는 2회 진행하는 것으로 우선 해석한다.
- 벽을 먼저 만든 뒤 입구와 출구를 정한다. 첫 입구 `(0, 0)` 또는 이전 출구 좌표는 생성 단계에서 통로로 예약한다.
- 플레이어 시작 위치(입구) 주변의 한 변 `(n // 2) + 1`인 정사각형을 제외한 통로 중 출구를 랜덤 선택한다. 4×4에서는 3×3, 6×6에서는 4×4를 제외하며, 짝수 변은 아래·오른쪽으로 한 칸 더 포함한다. 맵 밖 영역은 무시하고 제외 영역을 안쪽으로 옮기지 않는다. 통로·벽·서로 다른 입구와 출구가 모두 존재하는지 검사한다.
- 벽은 파괴할 수 있으므로 입구와 출구 사이에 처음부터 열린 길이 있어야 한다는 조건은 추가하지 않는다.
- 다음 미로의 입구는 직전 미로 출구 좌표를 그대로 사용한다. 묶음 안에서는 크기가 같으므로 좌표 변환이 필요 없다.

### 생성 규칙 중 확정이 필요한 부분과 초기 제안
- ‘행 또는 열 기준 절반’은 모든 행과 열을 동시에 만족하는지 불명확하다. 초기에는 **각 행에 n/2개의 벽**을 랜덤 배치하는 방식으로 제안한다. 4×4는 총 8개, 6×6은 총 18개가 된다.
- 벽이 칸인지 칸 사이 경계인지 원문만으로 확정할 수 없다. 위 칸 단위 표현은 구현 제안이며, 기획 확정 사항으로 취급하지 않는다.
- 전투 후 크기를 다시 추첨할 때 6×6의 출구 좌표를 4×4에 유지할 수 없는 경우가 있다. 이번 범위에서는 전투 후 생성을 구현하지 않으며, 이후 연결 전에 크기 선택과 좌표 유지 규칙을 정해야 한다. 좌표를 임의로 잘라내지 않는다.

## 입력과 벽 파괴
- 미로의 방향키는 위·아래·왼쪽·오른쪽 인접 칸을 대상으로 한다. 원문 조작표의 누락된 미로 항목은 이 방식으로 보완하는 것을 제안한다.
- 대상이 통로이면 즉시 한 칸 이동한다. 맵 밖이면 위치를 유지한다.
- 대상이 벽이면 첫 입력에 벽의 내구도를 2에서 1로 낮추고, 두 번째 입력에 통로로 바꾼다.
- 초기 제안: 타격 횟수는 벽마다 유지하고, 파괴 입력에서는 제자리에 남는다. 파괴된 칸 진입은 다음 입력으로 처리한다. 연속 두 번 입력 여부와 파괴 즉시 진입 여부는 기획 확정이 필요하다.
- 키를 누르고 있는 것만으로 두 번 공격되지 않게 한다. 한 번 누르고 떼는 동작을 한 입력으로 처리하며 자동 반복 입력은 사용하지 않는다.
- 캐릭터 좌표는 판정이 끝난 뒤 갱신한다. 첫 타격 벽과 파괴 완료는 색상 등으로 구분해 보여준다.

## 실행 흐름
1. 실행 즉시 크기를 추첨하고 첫 미로를 생성한다. 플레이어를 왼쪽 위 입구에 둔다.
2. 매 프레임 이벤트를 받고, 방향키 입력을 미로 규칙에 전달한다.
3. 이동 결과에 따라 플레이어 위치와 벽 표시를 갱신한다.
4. 출구에 도착하면 완료 횟수를 증가시킨다.
5. 남은 미로가 있으면 직전 출구를 입구로 사용해 새 미로를 자동 생성한다.
6. 4×4 3회 또는 6×6 2회가 끝나면 ‘미로 완료 · 전투 연결 예정’ 화면으로 전환하고 미로 입력을 중지한다.

- 화면에는 미로 크기, 현재 진행 횟수, 플레이어, 입구, 출구, 벽 상태를 표시한다.
- README의 ‘5초 제한’은 기준 기획에 없으므로 적용하지 않는다. 시간 초과 게임오버도 추가하지 않는다.
- 제약 안내 1~2초는 향후 전투와 제약 시스템을 연결할 때 구현한다. 첫 미로 → 전투에서는 제약을 발동하지 않는다.

## 구현 순서
1. `maze.py`: 데이터 구조, 생성, 필수 요소 검사, 이동·벽 파괴 판정을 작성한다.
2. `character.py`: 좌표와 방향 상태, 기본 도형 표시를 작성한다.
3. `BulBreak.py`: pico2d 실행 루프, 방향키 입력, 그리기 호출을 연결한다.
4. `BulBreak.py`: 크기별 횟수, 출구 좌표 전달, 완료 화면을 연결한다.
5. 기능 확인 후 기존 리소스를 적용하고 이동·타격 표시를 다듬는다.

## 완료 확인 기준
- 여러 번 생성해도 크기, 벽 수, 필수 요소, 첫 입구 좌표 규칙이 유지된다.
- 네 방향 이동, 맵 경계 차단, 벽 첫 타격·두 번째 타격·파괴 후 이동이 정상 작동한다.
- 키를 길게 눌러도 입력 한 번으로 벽이 파괴되지 않는다.
- 출구 진입 한 번에 완료 횟수는 한 번만 증가하고, 새 미로의 입구가 이전 출구와 일치한다.
- 4×4는 3회, 6×6은 2회 후 완료 화면으로 전환된다.
- 플레이 중 방향키 외 조작을 요구하지 않으며, 단계 전환 시 게임오버가 발생하지 않는다.
- 핵심 생성·이동·파괴·진행 규칙은 자동 검증하고, 화면 표시와 실제 키 입력은 실행해서 확인한다.

## 15초 강제 종료 및 화면 규칙 — 구현 완료
- `codes/game_framework.py`에서 미로·전투 진입마다 0~15초의 독립 타이머를 관리한다. 새 미로 진입과 재시작 시 초기화하며 일반 입력으로 연장하지 않는다. 메뉴·가이드에서는 동작하지 않는다.
- 15초 도달 시 게임오버 처리하고 큰 흰색 한글로 “그냥 다른게임하러가세요”를 표시한다. 기존 타이머·체력으로 먼저 게임오버가 되면 기존 게임오버를 유지한다. 아래는 재시작, 위는 시작 화면 복귀다.
- 시작 화면 글꼴은 별도 지시가 없으면 흰색이다. 구분이 필요하면 검은색 계열을 제외한 색을 사용할 수 있다.

## 게임오버 선택 및 작업 단위 — 최신 확정 사항
- 게임오버 기준은 동시에 적용하지 않고 새 게임·재시작마다 하나를 무작위로 지정한다. 현재 추첨 대상은 1번·2번이며, 3번은 추첨에서 제외한다.
- 선택한 기준은 연속 미로 진행 중 유지한다. 1번은 무행동 타이머만, 2번은 체력 규칙만 적용한다. 15초 강제 종료는 3번 전용이며 현재 플레이에서는 적용하지 않는다.
- 게임 화면 위쪽에 선택된 게임오버 기준과 해당 타이머·체력 정보를 표시한다. 가이드 설명은 한글로 작성한다.
- 작업은 Markdown에 먼저 기록하고 커밋한 후 코드를 수정한다. 코드 커밋은 파일별로 나누고, 각 커밋의 추가·삭제 합계는 최대 20줄로 제한한다.
- 이 절은 이전의 동시 적용·공통 15초 제한 설명보다 우선한다.
